Asignación de Variables con Desempaquetado

# 1. El resto al final:
azul, verde, *resto = colores
print(otros)
\end{lstlisting}
['rojo', 'negro']
# 2. El resto al principio:
*resto, negro = colores
print(otros)
\end{lstlisting}
['azul', 'verde', 'rojo']
# 3. El resto en medio (Sandwich):
azul, *resto, negro = colores
print(otros)
\end{lstlisting}
['verde', 'rojo']

⏱️ 3 min

  • Fijaos en el ejemplo de los colores.
  • En el primer caso: La variable `azul` se queda con el valor 'azul' porque va PRIMERA. La variable `verde` con 'verde' porque va SEGUNDA.
  • Y la variable `*resto` (la que tiene el asterisco) actúa de escoba y recoge todo lo que sobra ('rojo' y 'negro').
  • Lo importante es la posicion respecto a las comas.

El Problema: ¿En qué posición está?

# Intento 1: Bucle for normal
ranking = ['Ana', 'Beto']
for persona in ranking:
    print(persona)
\end{lstlisting}
Ana Beto
# Intento 2: Usando indices manuales
for i in range(len(ranking)):
    # Acceso manual con [i] y correccion de indice (+1)
    print(i + 1, ":", ranking[i])
\end{lstlisting}
1 : Ana 2 : Beto

⏱️ 2 min

  • Tenemos una lista de corredores: Ana, Beto...
  • Problema: Quiero imprimir '1. Ana', '2. Beto'.
  • Intento 1: Si uso `for x in lista`, pierdo el número.
  • Intento 2: Si uso `range(len())`, funciona, pero el código es feo, largo y difícil de leer.

La Solución: enumerate

#           0       1       2
ranking = ['Ana', 'Beto', 'Carla']

# 1. Veamos que genera realmente enumerate:
# 1. El indice (contador automatico)
# 2. El dato (nombre)

for i, nombre in enumerate(ranking):
    print(i + 1, ":", nombre)
\end{lstlisting}
1 : Ana 2 : Beto 3 : Carla

⏱️ 2 min

  • Aquí está la solución elegante: `enumerate`.
  • Esta función nos permite pedirle al bucle DOS cosas a la vez.
  • La primera variable (`i`) será nuestro contador automático (0, 1, 2...).
  • La segunda variable (`nombre`) será el dato real.
  • Fijaos que ya no usamos corchetes `[]` ni calculamos longitudes. Es mucho más limpio.

Buenas Prácticas: La función main

# MAL: Código suelto (Global)
print("Arrancando...")
x = 5

# BIEN: Todo ordenado en su sitio
def main():
    print("Arrancando...")
    x = 5
\end{lstlisting}

⏱️ 2 min

  • ¿Por qué definimos `main()` en lugar de escribir código a lo loco?
  • 1. Orden. Sabemos dónde empieza todo.
  • 2. Limpieza. Las variables dentro de `main` mueren al terminar `main`. No se quedan flotando (variables globales) consumiendo memoria o causando bugs.

El Guardián: if __name__ == "__main__"

def main():
    print("Soy el programa principal")

# Si el archivo se ejecuta directamente...
if __name__ == "__main__":
    main() # ...entonces arranca.
# Si se importa como modulo, NO hace nada.
\end{lstlisting}

⏱️ 4 min (Concepto Difícil)

  • Este bloque raro `if __name__...` lo veréis siempre.
  • Es un control de seguridad. Imaginad que sois una librería.
  • Pregunta: '¿Me has dado al Play a mí directamente?'. Si es sí, ejecuto `main()`.
  • Si es no (porque alguien me ha importado para usar mis funciones), me quedo quieto.
  • Copiad y pegad esto en todos vuestros scripts.

¿Qué es una Clase? (El Molde)

⏱️ 5 min

  • Analogía clave: El Molde y la Galleta.
  • La Clase es el molde. Es abstracto. No se puede comer.
  • El Objeto es la galleta. Es real. Tienes una, te la comes.
  • Con un solo molde (Clase Estudiante) podemos hacer mil galletas distintas (Juan, Ana, Luis...).

Partes de una Clase

⏱️ 2 min

  • Es simple: Datos y Acciones.
  • Atributos = Variables pegadas al objeto (Color, Edad).
  • Métodos = Funciones pegadas al objeto (Correr, Saltar).

El Nacimiento: __init__

class Estudiante:
    def __init__(self, nombre, nota):
        # "MI nombre es igual al nombre que me pasan"
        self.nombre = nombre
        self.nota = nota

# Creando el objeto (La galleta)
# Python llama a __init__ por nosotros
juan = Estudiante("Juan", 5) 
print(juan.nombre) # Acceso directo (Publico)
\end{lstlisting}
Juan

⏱️ 5 min (Concepto Clave)

  • El `__init__` es el nacimiento del objeto. Python lo llama AUTOMÁTICAMENTE.
  • self: Es la referencia a sí mismo. Significa 'MI'.
  • Cuando ponemos `self.nombre = nombre`, estamos diciendo: 'Guarda en MI mochila el nombre que me han pasado'.

¿Por Qué el __? (Privacidad)

juan.nota = 1000 # ¡Trampa! Esto es valido si es publico
\end{lstlisting}
class Estudiante:
    def __init__(self, nombre, nota):
        self.__nombre = nombre # Protegido
        self.__nota = nota     # Protegido

# juan.__nota = 1000  -> ERROR (Python no lo encuentra)
\end{lstlisting}

⏱️ 3 min

  • Problema: Si dejamos la nota pública, alguien podría poner `juan.nota = 1000` y romper el sistema.
  • Solución: Los dos guiones bajos `__` son un candado.
  • Solo el propio objeto puede tocar sus variables privadas desde dentro.

Añadiendo un Método (Acción)

class Estudiante:
    def __init__(self, nombre, nota):
        self.__nombre = nombre; self.__nota = nota
        
    # DEFINICION: self es obligatorio aqui
    def estudiar(self, horas):
        self.__nota += (horas * 0.1)
        print(f"Nueva nota: {self.__nota}")

juan = Estudiante("Juan", 5)

# LLAMADA: NO pasamos self (Python pasa a 'juan' por nosotros)
juan.estudiar(10) 
\end{lstlisting}
Nueva nota: 6.0

⏱️ 3 min

  • OJO AQUÍ: La trampa del `self`.
  • Al DEFINIR la función `estudiar`, tengo que escribir `self` porque necesito saber QUIÉN estudia.
  • Pero al LLAMARLA `juan.estudiar(10)`, NO escribo `juan` dentro del paréntesis.
  • ¿Por qué? Porque Python hace magia: coge lo que hay a la izquierda del punto (`juan`) y lo mete como primer argumento invisible.

La Magia del self (¿Qué pasa por debajo?)

# TU ESCRIBES:
juan.estudiar(5)

# PYTHON REALMENTE EJECUTA:
# Pasa el objeto 'juan' como primer argumento (self)
Estudiante.estudiar(juan, 5)
\end{lstlisting}

⏱️ 2 min

  • Si alguna vez os liáis con el número de argumentos, acordaos de esta diapositiva.
  • Cuando llamáis a `juan.estudiar(5)`, Python coge a `juan` (el sujeto) y lo mete a la fuerza como primer argumento.
  • Por eso la función recibe DOS cosas: `juan` (que se llama `self` dentro) y `5` (las horas).
